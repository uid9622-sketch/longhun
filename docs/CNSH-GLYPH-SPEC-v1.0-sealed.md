## 一、语法定位与文件骨架

CNSH 字元语法是「CNSH 数字甲骨文字元立碑工程」的字形定义语言：用**中文关键字 + JSON 结构**描述一个汉字的全部笔画路径与渲染属性，使字元可以在任何引擎中被确定性地重建为矢量图形（SVG）。

一个字元文件（`.cnsh` / `.json`）由两部分组成：

```text
┌─────────────────────────────┐
│ 签章头（3 行 # 注释封印）    │  ← 身份层：DNA / CONFIRM / SEAL
├─────────────────────────────┤
│ JSON 体（字元定义）          │  ← 数据层：字符集 + 审计 + 扩展
└─────────────────────────────┘
```

解析规则：**以 `#` 开头的行属于签章头，解析器读取 JSON 前必须先剥离；签章头不参与 JSON 解析，但参与身份与完整性校验。**

---

## 二、签章头：三行封印

每个字元文件、每个引擎脚本的开头必须是三行封印，顺序固定：

```text
# DNA: #龍芯⚡️丙午·丙申·庚戌·䷙大畜-SCRIPT-MANAGER-v1.2-UID9622
# CONFIRM: #CONFIRM🌌9622-ONLY-ONCE🧬LK9X-772Z
# SEAL: #ZHUGEXIN⚡️2025-🇨🇳🐉⚖️♠️🧚🏼‍♀️❤️♾️-DEVICE-BIND-SOUL
```

| 行 | 关键字 | 语义 |
| --- | --- | --- |
| 1 | `DNA` | 时空锚定（干支 + 卦象）+ 脚本管理者版本 + 所有者 |
| 2 | `CONFIRM` | 一次性授权确认令牌 |
| 3 | `SEAL` | 设备与灵魂绑定封条 |

约束：

- 三行缺一不可，顺序不可调换。
- 新派生文件继承封印，并追加自己的 `DNA追溯码`（见第三章），不得覆盖原封印。
- 缺少封印的文件视为**无来源派生**，引擎应拒绝载入。

## 三、JSON 体：顶层字段规范

### 3.1 必选字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `来源标注` | string | 固定格式 `#ZHUGEXIN⚡️ | UID9622 龍魂体系` |

### 3.2 可选字段（按引入版本）

| 字段 | 类型 | 引入版本 | 说明 |
| --- | --- | --- | --- |
| `版本信息_cnsh9622` | object | v0003 | 版本号、创建日期、字符总数、画布尺寸 |
| `渲染参数_cnsh9622` | object | v0003 | 默认笔画宽度、颜色、填充模式、端点与连接样式 |
| `三色审计_cnsh9622` | object | v0003 | 红/黄/绿三级检查项与结果（见第七章） |

## 四、字符集与字元结构

`字符集_cnsh9622` 的每个键是一个汉字（如 `龍`、`中`、`华`、`民`、`魂`），值为字元对象：

| 字段 | 必选 | 说明 |
| --- | --- | --- |
| `字元标识` | 是 | 全局唯一 ID，格式 `CNSH-NAME-NNNN`，如 `CNSH-DRAGON-0002`、`CNSH-MIDDLE-0002`、`CNSH-SOUL-0008` |
| `笔画路径_cnsh9622` | 是 | 笔画指令数组（见第五章） |
| `字符状态` | 否 | 字元生命周期状态 |
| `笔画数量` | 否 | 笔画计数（冗余校验用） |
| `重心偏移` | 否 | 字元级重心调整（v0013 引入） |

命名规则：

- `NAME` 使用字元语义的英文大写单词（DRAGON / MIDDLE / HUA / PEOPLE / SOUL）。
- `NNNN` 为四位数字序号，随结构代数递增；同一汉字在不同结构代数可有不同序号（如龍：`CNSH-DRAGON-0002` → `CNSH-DRAGON-0008`）。
- 旧标识永久保留在对应版本库中，不得回收复用。

## 五、笔画路径 DSL

### 5.1 三种指令

笔画路径是有序指令数组，只有三种指令类型：

| 类型 | 参数 | 语义 | SVG 映射 |
| --- | --- | --- | --- |
| `移动到` | `坐标: [x, y]` | 抬笔移动到新起点 | `M x y` |
| `直线段` | `终点: [x, y]` | 从当前点画直线到终点 | `L x y` |
| `三次曲线` | `控制点: [[x1,y1],[x2,y2],[x3,y3]]` | 从当前点以两个控制点画三次贝塞尔曲线，终点为第三个点 | `C x1 y1, x2 y2, x3 y3` |

### 5.2 执行语义

- 引擎维护一个「当前点」，初始为空。
- `移动到` 只改变当前点，不产生笔画。
- `直线段` / `三次曲线` 从当前点画线，并把当前点更新为终点。
- 三次贝塞尔插值（引擎实现基准）：

```text
B(t) = (1-t)³·P0 + 3(1-t)²t·P1 + 3(1-t)t²·P2 + t³·P3，t ∈ [0,1]
```

其中 `P0` 为当前点，`P1 P2 P3` 为 `控制点` 数组的三个点。

### 5.3 坐标系

- 画布为正方形矢量空间，基准 `viewBox="0 0 600 600"`（v0003 起以 `版本信息_cnsh9622.画布尺寸` 为准）。
- 坐标为整数像素，`x` 向右、`y` 向下。
- 默认渲染：白底、黑 stroke、`stroke-width: 8`、`stroke-linecap/linejoin: round`、无填充。

### 5.4 最小笔画示例

```json
"中": {
  "字元标识": "CNSH-MIDDLE-0002",
  "笔画路径_cnsh9622": [
    { "类型": "移动到", "坐标": [200, 80] },
    { "类型": "直线段", "终点": [200, 520] },
    { "类型": "移动到", "坐标": [100, 300] },
    { "类型": "直线段", "终点": [300, 300] }
  ]
}
```

## 六、笔画扩展属性层

字元语法采用**逐层扩展**模式：每个新版本在笔画指令上追加一种可选属性，旧属性全部保留。扩展属性写在笔画指令对象内，与 `类型` 平级。

| 属性 | 引入版本 | 作用层 | 语义 |
| --- | --- | --- | --- |
| `力度` | v0005 | 笔画力度层 | 运笔力度权重，影响笔画粗细表现 |
| `棱角` | v0006 | 棱角断锋层 | 笔画转折处的棱角/断锋锐度 |
| `停顿` | v0007 | 节奏停顿层 | 行笔节奏中的停顿标记 |
| `层级` | v0008 | 层级遮挡层 | 笔画前后叠放层级（整数，大者在上） |
| `断续` | v0009 | 断续残缺层 | 碑刻风化的断续、残缺表达 |
| `侵蚀` | v0010 | 侵蚀风化层 | 笔画边缘侵蚀程度 |
| `纹理` | v0011 | 纹理石刻层 | 石刻表面纹理质感 |
| `墨色` | v0012 | 墨色浓淡层 | 墨色浓淡等级 |
| `重心偏移`（字元级） | v0013 | 重心调整层 | 整字重心微调 |
| `组合排版_cnsh9622`（顶层） | v0014 | 多字排版层 | 多字横排/竖排与字间距 |
| `阴影` | v0015 | 阴影立体层 | 阴影参数 `[x偏移, y偏移, 扩散]`，赋予立体感 |

带扩展属性的笔画实例（v0015 龍字片段）：

```json
{ "类型": "直线段", "终点": [460, 180], "力度": 20, "阴影": [3, 3, 2], "层级": 1 },
{ "类型": "三次曲线", "控制点": [[260, 260], [240, 360], [300, 520]], "力度": 22, "阴影": [4, 4, 3], "层级": 2 }
```

兼容规则：**引擎遇到不认识的扩展属性必须忽略而不是报错；不认识指令 `类型` 才拒绝渲染。**

## 七、三色审计块

`三色审计_cnsh9622` 是字元库的自检声明，分红、黄、绿三组，每组含 `检查项` 数组与 `结果`：

```json
"三色审计_cnsh9622": {
  "红色": { "检查项": ["无西方术语", "无英文变量", "无国际标准"], "结果": "通过" },
  "黄色": { "检查项": ["仅直线段与三次贝塞尔", "仅JSON/SVG", "阴影自主定义"], "结果": "通过" },
  "绿色": { "检查项": ["结构可运行", "阴影立体可表达"], "结果": "通过" }
}
```

合并规则与龍魂生态一致：**任一红色 → 整体红色；无红有黄 → 整体黄色；全绿 → 整体绿色；未知不得视为绿。**

## 八、CNSH 编号体系

生态内所有模块使用统一编号格式：

```text
#CNSH · 领域 · 名称 · 序号
```

已观察实例：

| 编号 | 模块 |
| --- | --- |
| `#CNSH·YIJING·CORE·001` | 易经 64 卦推演核心 |
| `#CNSH·YIJING·ENGINE·001` | 推演引擎算法实现 |
| `#CNSH·HEXAGRAM·PARSER·001` | 卦象解析引擎（384 爻辞） |
| `#CNSH·SOLAR·TERM·001` | 二十四节气加权算法 |
| `#CNSH·TIME·PREDICT·001` | 时间预测系统 |
| `#CNSH·WUXING·BALANCE·001` | 五行平衡模块 |

字元侧对应物：`DNA追溯码`（库级，如 `#ZHUGEXIN⚡️-CNSH-STELE-0002`）与 `字元标识`（字元级，如 `CNSH-DRAGON-0002`）。

## 九、配套文件与引擎生态

每个字元文件标配三类伴生文件：

- `*.json.asc`：PGP 签名（`-----BEGIN PGP SIGNATURE-----`），用于来源与完整性校验。
- `*.glyph-backup`：字元备份，禁止静默覆盖的物证。
- 同名渲染产物：`CNSH_字元_<字>_vNNNN.svg`。

已实现引擎（UID9622 系列）：

- `render_cnsh.py`：字元渲染器（载入 `.cnsh` → 输出 SVG）。
- `CNSH字元引擎_UID9622_审计版.py` / `CNSH字元引擎_UID9622_批量版.py`：审计与批量渲染。
- 专项引擎：力度、棱角、层级、节奏、断续、侵蚀、纹理、墨色、重心、排版、组合引擎各一。
- `CNSH引擎管理器_UID9622.py`：引擎统一调度。
- `CNSH画匠系统`：系统配置 + AI 辅助接口。

## 十、合法性校验规则

一份合法字元文件必须同时满足：

1. 三行封印齐全且顺序正确。
2. 剥离封印后是合法 JSON。
3. 四个必选顶层字段齐全，`DNA追溯码` 全库唯一。
4. 每个字元含 `字元标识` 与非空 `笔画路径_cnsh9622`。
5. 指令 `类型` 仅为 `移动到` / `直线段` / `三次曲线`，参数键与类型匹配（`坐标` / `终点` / `控制点`）。
6. 首个产生笔画的指令之前必须有 `移动到`。
7. 坐标在画布范围内，`三次曲线.控制点` 恰为三个点。
8. 扩展属性只追加、不改名、不删除旧属性。
9. 有三色审计块时，结果与检查项一致。
10. 新版本只追加演化，禁止静默覆盖旧版本。

## 十三、治理原则

- 字元有碑：每个字元有唯一标识与追溯码。
- 版本只增不删：新属性以新版本引入，旧版本永久只读。
- 签章即身份：无三行封印的文件不予载入。
- 未知不冒充：引擎忽略未知扩展属性，但不得伪造其语义。
- 本源不丢：任何渲染产物都必须能回到字元 JSON 本源。
